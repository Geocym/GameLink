# v0.2.4 reliability preview

Build in Visual Studio with .NET 10 Windows Desktop. Keep v0.2.3.1 as fallback.

- Start Streamer.bot and GameLink; send a synthetic test event. Pending should return to zero.
- Stop Streamer.bot; send two test events. Check queue/*.json under %AppData%/GameLink. Exit GameLink from tray, restart it while Streamer.bot is stopped, then start Streamer.bot. Verify both original IDs arrive and recovered flag is true. Test events can execute real actions: use a safe test action.
- Enable both routes and verify separate acknowledgements. A permanently rejected destination blocks FIFO until corrected; pending routes are captured at enqueue time. Do not delete pending files unless intentionally discarding events.
- Check logs/gamelink.log, metadata/*.json and history/*.json. History snapshots are not offline unlock recovery; startup still suppresses historical alerts.
- Artwork and rarity behavior remain as before. No Windows build/runtime test was performed by the author.
- Delivery timestamp is attempt time, not acknowledgement time. Attempt count is per event across destinations. Delay flag threshold is five seconds or retry/recovery.
- Queue persists after enrichment, not at initial detection; crashes during enrichment and disk errors can lose events. DPAPI, background prefetch, offline achievement recovery and configurable retry intervals are deferred.
