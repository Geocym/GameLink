# GameLink 0.2.4.1

Build with .NET 10 Windows and restore NuGet packages (ProtectedData 10.0.0).
Back up settings.json before upgrading: legacy plaintext passwords are migrated to current-user DPAPI ciphertext in settings.json. Older builds cannot read the encrypted password; re-enter it if rolling back. Never share the backup.

- Verify connection with an existing password and restart. Inspect settings.json for absence of plaintext password (do not share it).
- Retry interval: change from 15 to 5 seconds and test offline queue recovery. Range 5–300 seconds.
- Disable persistent logging; live log should continue, existing disk logs remain. Re-enable and check rotation at 2 MB, four archives. Live textbox trims at 200,000 characters.
- With recovery disabled, unlock while GameLink is closed, then launch; no historical alert expected. With recovery enabled, repeat on a game already baselined in history; expect isRecoveredAchievement=true and original unlockTimestamp. First-time caches are baselined, not replayed. Recovery events do not count toward current session. Recovery uses saved achievement slots and requires a timestamp.
- Test a deliberately nonexistent specific action alongside a valid generic action; explicit rejection should archive the destination in rejected/ and allow subsequent events to proceed. Transport errors remain queued. Restore the valid route afterwards. Archived rejections require manual inspection; no automatic replay.
- Repeat v0.2.4 queue and Steam regression tests.

Limitations: no Windows compilation in authoring environment. Background artwork prefetch deferred; artwork remains on demand. History snapshots are written before event enqueue as in 0.2.4, so a crash during enrichment can lose a detection. Recovery only compares previously known installed game caches at first scan of an account context. Explicit server rejections are archived even if temporary; no expiry or replay UI yet. Log rotation has not been stress tested.
