# v0.2.2 experimental local achievement monitor
Extract separately; exit the old instance via its tray menu. Build as before. No API key.
Start Steam and GameLink, wait for the achievement diagnostics message, then launch a game and earn a genuine Steam achievement. Keep GameLink running for at least 30 seconds after closing the game. Copy the GameLink log (review for private information first), tell us the game and achievement name and whether Streamer.bot received achievement.unlocked. No need to reset achievements or edit Steam files.

The monitor tails new complete lines in logs/stats_log.txt, and reports changed .bin files in appcache/stats. It emits an experimental unlock only when a line explicitly states an unlock and contains a recognized app ID for a currently running installed game. This log format is hypothetical, not verified on a live Steam client. Cache files are observed, not decoded. No guaranteed detection; missing unlocks are useful diagnostic results. Existing log content is skipped on startup/account change/truncation; duplicate matches are suppressed in memory per account/game/achievement. No persistent deduplication or delivery queue. Metadata is not enriched (name is the internal identifier). Raw log diagnostics stay in GameLink and are not sent to Streamer.bot. The existing WebSocket implementation is unchanged; reconnect issue deferred. Disable Steam monitoring in settings to stop all Steam diagnostics. No Windows compilation or real unlock test performed here.
